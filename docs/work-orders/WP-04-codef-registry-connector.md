# WP-04. CODEF 등기부 커넥터

- 상태: **대기 (차단 해제)** — CODEF Client ID/Secret 확보·검증 완료 (2026-07-07 OAuth 토큰 발급 HTTP 200, expires_in 604799). IROS 계정 확보. 전자민원캐시만 미확보(데모 필요 여부 가이드 확인) | 선행: WP-01(완료), WP-03(출력 스키마 정합)
- 시작 전 필독: `AGENTS.md`, `decision-log.md` D-008, `06-tech-blueprint.md` §2-3, CODEF 개발가이드(https://developer.codef.io — 부동산등기부등본 상품)

## 목적
CODEF API로 특정 부동산의 등기사항전부증명서를 열람·파싱해 WP-03 룰 엔진의 입력(권리 목록)으로 정규화하는 NestJS 모듈. **on-demand + 사건 단위 캐시** (D-008 — 원가 통제 핵심).

## 필요 자격증명 (.env — 채팅·코드·로그에 노출 금지, 규칙 8)
| 항목 | env 키 | 상태 |
|---|---|---|
| CODEF 공개키 (RSA 암호화용, 비밀 아님) | `CODEF_PUBLIC_KEY` | ✅ 확보 (.env.example에 기재) |
| CODEF Client ID / Secret (데모) | `CODEF_CLIENT_ID/SECRET` | ❌ 사용자 발급 대기 — codef.io 계정 > 마이페이지 |
| 인터넷등기소 회원 ID/PW | `IROS_MEMBER_ID/PW` | ❌ 사용자 준비 (PW는 공개키로 RSA 암호화해 전송) |
| 전자민원캐시 번호/비번 (열람 실비 700원) | `IROS_EPREPAY_NO/PASS` | ❌ 데모 필요 여부 가이드 확인 |

## 요구사항
1. **인증**: OAuth2 client_credentials 토큰 발급·갱신(만료 캐시). 데모 도메인 `CODEF_API_BASE` 사용 (규칙 13)
2. **암호화 유틸**: `CODEF_PUBLIC_KEY`로 비밀번호 필드 RSA 암호화 (node:crypto, PKCS#1 v1.5 — CODEF 가이드로 패딩 방식 확인)
3. ⚠️ **착수 시 최우선 확인** (가이드 원문 기준으로 확정 후 구현 — 추정 구현 금지): 정확한 상품 엔드포인트·요청 파라미터(고유번호 vs 주소 검색), 응답 포맷, 데모 데이터 제약. 확인 결과를 이 파일 하단에 추가 기록
4. **정규화**: 응답(갑구·을구 권리 내역) → WP-03 입력 DTO 매핑. 매핑 불가 항목은 `NEEDS_REVIEW`로 보존 (버리지 않음)
5. **캐시** (규칙 10): 물건(사건) 단위 — 동일 물건 재조회 시 발급 호출 0회. 캐시 무효화 기준(기일 변경 시 재발급 여부)은 서비스 옵션으로
6. **동시성**: 같은 물건 동시 요청 시 발급 1회만 (락 또는 in-flight dedup — 700원 중복 과금 방지)
7. **예외 구분** (규칙 6): 재시도 가능(타임아웃/5xx) vs 불가(인증 실패/잔액 부족/대상 없음) — 불가 예외는 명확한 도메인 에러로
8. 로그: 요청 ID·물건 키·과금 발생 여부 기록, 계정·비밀번호·등기부 내 개인정보 값 로그 금지 (규칙 7·8)
9. 테스트: 실 API는 fixture 녹화 후 mock (정상/암호화 오류/잔액 부족/캐시 적중/동시 요청)
