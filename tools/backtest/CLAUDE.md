# tools/backtest/ — 스코프 작업 지침

이 폴더의 파일을 다룰 때만 로드된다(온디맨드). 공통 행동규칙은 루트 `CLAUDE.md`,
프로젝트 표준·구현기준 22개는 `AGENTS.md`, 다음-할일은 `NEXT.md`를 따른다.

## 목표

WP-11 룰 역채점. 권리분석 규칙·가설(H1~)이 실제 매각결과를 예측하는지 SQL로 채점한다.
지시서: `docs/work-orders/WP-11-rule-backtest.md`

## 소유 경로

`backtest_report.sql` (임시 분석 쿼리).
채점 결과를 화면에 서빙하는 코드는 이 폴더가 아니다 — `apps/api/src/backtest`,
`apps/web/app/admin/backtest`. 쿼리 로직을 옮길 때 두 곳이 어긋나지 않게 할 것.

## 핵심 관례 — 반복해서 틀린 함정 3종

같은 종류의 집계 오류로 이미 세 번 고쳤다. 새 가설을 채점할 때마다 이 셋을 먼저 확인한다.

1. **매각결과는 매각기일 행만 센다** (`9cf88da`). 매각기일이 아닌 행을 낙찰/유찰로 세면
   분모가 부풀어 결과가 뒤집힌다.
2. **관측 윈도우로 제한한다 — 생존편향** (`209c5cd`). 아직 결과가 나오지 않은 물건을
   모집단에 넣으면 "안 팔린 물건"이 과소 집계된다.
3. **경매 단위(unit)로 센다** (`4aaaac0`). 사건 단위와 물건 단위를 섞으면 개수가 어긋난다.

추가로: 파싱 품질이 낮은 공고는 채점에서 제외(gating)한다 (`147ca93`) — 파서가 버린 행 수
(`notice_tenant_reject_count`)를 게이트로 쓴다.

## 검증

쿼리 결과는 자동 테스트가 없다. 채점을 바꿨으면 **표본 수·분모·관측 윈도우를 먼저 출력해
눈으로 확인**하고, 판독 가능한지(H3처럼 판독 불가로 끝나지 않는지)를 지시서에 기록한다.
