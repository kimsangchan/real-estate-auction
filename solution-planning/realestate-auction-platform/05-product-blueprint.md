# Product Blueprint (PRD 초안) — 경매 입문자용 부동산 경매 플랫폼

작성일 2026-07-07. 근거: decision-log D-001~D-014, 01-domain-discovery. Spec Kit 사용 시 이 문서를 /specify 입력으로 사용.

## 1. 문제 정의

경매는 시세보다 싸게 집을 살 수 있는 합법적 경로지만, 일반인에게는 세 개의 벽이 있다.

1. **정보의 벽**: 법원경매정보 사이트는 무료지만 서류(매각물건명세서 등) 원문을 해석할 수 없다. 아실이 무료로 서류·등기부를 보여주지만 **해석은 여전히 사용자 몫**이다 (01 §4-3).
2. **비용의 벽**: 해석(권리분석)을 제공하는 유료 사이트는 연 65만~93만원, 전문가 지향이다.
3. **용어의 벽**: "말소기준권리", "대항력" 같은 용어 자체가 진입 장벽이다.

**이 제품은 룰 기반 자동 권리분석을 입문자의 언어로 제공해, "이 물건을 낙찰받으면 총 얼마가 드는지, 무엇을 현장에서 확인해야 하는지"를 무료로 알려준다.**

## 2. 타깃 사용자 (D-001 사용자 확정)

- **주 타깃**: 경매 입문 일반인 — 실수요(내집 마련) 또는 소액 투자로 경매를 처음 접하는 사람. 부동산 용어 지식 없음.
- 부 타깃(Standard 이후): 경험 있는 소액 투자자, 개업공인중개사(전문가 연결 공급자).

## 3. 포지셔닝 / 경쟁 차별화 (01 §4 근거, 아실 제보 반영)

| 경쟁자 | 그들이 하는 것 | 우리가 다르게 하는 것 |
|---|---|---|
| 아실 (무료) | 지도 경매 물건 + 서류·등기부 원문 열람 | 원문이 아니라 **해석된 결과**: 인수/말소 자동 분류, 총 인수금액 자동 계산, 용어 풀어쓰기 |
| 리치고 (AI) | GPT 생성형 권리분석 요약 | **룰 기반**(변호사법 경계 안전) + 판단 문구 없이 사실 정리 + 근거 조항 표시 — "왜 이렇게 분류됐는지" 추적 가능 |
| 유료 3사 (연 65만~93만원) | 전문가용 심층 데이터 | 입문자에게 필요한 층위만 무료로, 3탭 이내 도달 (UX-07) |
| 네이버·KB·다방 | 일반 매물 (경매 없음/명목상) | 경매 특화. 일반 매물은 Standard에서 교차 뷰로 진입 |

핵심 방어선: 이 제품의 차별화는 데이터(모두에게 공개된 공공데이터)가 아니라 **① 룰 엔진의 정확도·신뢰성 ② 입문자 UX**에 있다.

## 3a. 앱 구성 방식(IA) 벤치마크 — 3사 구성 × 토스 UX × 경매 콘텐츠

사용자 의도 명확화(2026-07-07): 3사 분석의 목적은 그들과의 매물 경쟁이 아니라 **검증된 앱 구성 방식을 가져오는 것**. 사용자가 이미 아는 화면 패턴을 따르는 것 자체가 토스 UX의 근거 법칙(L-01 제이콥의 법칙)과 일치한다 — 새로 배울 개념은 "경매 도메인"만으로 한정하고, 화면 문법은 3사 표준을 유지한다.

### 3사 구성 요소 → 우리 앱 매핑

| 3사의 구성 요소 (근거: 01 §4-1) | 채택 원본 | 우리 앱(경매 버전) | 적용 토스 원칙 |
|---|---|---|---|
| 전체 화면 지도 홈 + 상단 검색바 + 필터 칩 + 하단 물건 목록 시트 | 네이버(지도 중심 매물 탐색), 다방(세부 필터) | 동일 구성, 마커만 경매 물건. 필터 칩: 유형·가격·기일·유찰·위험 플래그 | L-01 (아는 패턴), L-04 (필터 그룹 ≤7) |
| 물건 상세: 가격 헤더 → 시세 그래프 → 정보 섹션 → 하단 고정 CTA | 3사 공통 상세 페이지 문법 | 가격 헤더 = 감정가·최저가·유찰 이력 / 그래프 = 주변 실거래가 비교(KB식 데이터 깊이) / **CTA = "권리분석 보기"** (문의 전화 대신) | T-08 (CTA는 다음 행동 그대로), L-03 (화면당 결정 1개) |
| 시세·통계 대시보드 | KB (데이터허브, AI시세) | 물건 상세 안의 "시세 컨텍스트" 섹션으로 축소 통합 — 별도 탭으로 빼지 않음 (MVP) | L-03, 힉의 법칙 |
| 세밀한 조건 필터 + 목록 우선 뷰 | 다방 (전월세 필터 UX) | 경매 조건으로 이식: 유찰 횟수·기일 임박·위험 플래그 필터. 지도⇄목록 토글 | L-05 (입력은 관대하게) |
| 관심 등록(찜) + 변동 알림 | 3사 공통 | 관심 물건 + 기일 변경·유찰 푸시 (F-06) | T-07 (맥락 없는 푸시 금지) |
| 허위매물 신고·검증 배지 | 네이버(KISO)·다방(확인매물) | 불필요 — 법원 공고 기반 "100% 실물건"을 신뢰 메시지로 표면화 | T-14 (정보 전달 목적 그래픽) |
| 하단 탭 내비게이션 (4~5개) | 3사 공통 | 4탭: 지도 홈 / 검색 / 관심·알림 / MY | L-04 (7±2) |
| 진입 즉시 팝업·이벤트 모달 (3사 관행) | **채택 안 함** | 비로그인 즉시 지도 진입 | T-04 (진입 방해 금지) — 3사 대비 개선점 |

### 3사 구성에 없는 우리 고유 화면

| 화면 | 구성 | 근거 |
|---|---|---|
| 권리분석 결과 | 결론 요약 카드(총 부담액) → 권리 타임라인(말소기준 시각화) → 임차인 카드 → 근거 펼침 | UX-02 (계산 0개), UX-03 (용어 병기), D-011 (판단 문구 금지) |
| 임장 체크리스트 | 물건별 자동 생성 체크리스트, 오프라인 저장 | F-04, UX-06 |
| 용어 도우미 | 인라인 툴팁 + 용어 사전 | UX-03, T-13 |

화면 상세 설계(와이어프레임)는 Phase 2 착수 시 이 매핑 표를 입력으로 진행하고, 각 화면은 UX-01~07 통과를 완료 기준으로 한다 (07-roadmap).

## 3b. 시각 디자인 체계 — DESIGN-meta × 도메인 적용 규칙

프론트 시각 시스템은 D-014에 따라 루트 `DESIGN-meta.md`를 기본으로 한다. 단, Meta 커머스 원본을 그대로 복제하지 않고 `docs/design/design-adaptation.md`의 도메인 매핑·치환·제외 규칙을 함께 적용한다.

- 시각 토큰·컴포넌트: `DESIGN-meta.md`의 컬러, 타이포그래피, 라운딩, 스페이싱, 컴포넌트 이름을 기준으로 한다.
- 도메인 치환: Optimistic VF는 Pretendard Variable로 치환하고, attention/warning 배지는 AA 대비를 만족하도록 `{colors.ink-deep}` 텍스트를 쓴다.
- 제외 패턴: `promo-banner`, `badge-promo-yellow`, 세일/판촉 히어로 카피는 MVP에서 쓰지 않는다.
- UX 라이팅: 문구와 플로우는 계속 토스 원칙(T-NN)·UX-01~07을 따른다. Meta의 영문 카피 톤은 참조하지 않는다.
- 구현 원칙: Phase 2부터 디자인 토큰은 `packages/` 하위 단일 소스로 코드화하고, 웹 CSS 변수와 RN 스타일 상수가 같은 토큰을 공유해야 한다.

## 4. 스코프 (D-002 사용자 확정 — S1 경매 특화 MVP)

포함: 아래 기능 명세 전부. 제외(이연): 일반 매물 광고(Standard), 입찰 대행·전문가 연결(Standard), 생성형 AI 요약(Enterprise, 변호사 검토 후), 대출 비교(Enterprise, 금소법 등록 후), 사용자 GPS 기반 "내 주변"(LBS 신고 회피 — 03-scope-options 참조).

## 5. 기능 명세 (EARS 패턴)

### F-01 지도 기반 물건 탐색
- 사용자가 지도를 이동·확대할 때, 시스템은 화면 영역 내 경매 물건을 갱신하고 400ms 이내 시각 피드백을 제공해야 한다 (UX-04).
- 물건 밀집 지역은 클러스터로 묶고, 지적편집도 레이어를 토글할 수 있어야 한다.
- 필터: 물건 유형(아파트/빌라/오피스텔/단독/토지), 감정가·최저가 범위, 매각기일, 유찰 횟수, 위험 플래그 유무. 필터 그룹당 항목 7개 이하 (L-04).

### F-02 물건 상세
- 사용자가 물건을 선택하면, 시스템은 감정가·최저가·기일 이력·법원 서류 3종 원문 링크·주변 실거래가 비교를 한 화면에 표시해야 한다.
- 감정평가서는 요지 발췌 + 법원 사이트 원문 링크로 제공한다 (저작권 보수 설계, 01 §3-2).

### F-03 자동 권리분석 (핵심 기능, D-011 경계 준수)
- 사용자가 권리분석 탭에 진입하면, 시스템은 등기부를 발급·파싱(on-demand, D-008)하여 다음을 표시해야 한다:
  - 말소기준권리 판별 결과 + "이 날짜 이후 권리는 낙찰로 사라져요" 식 풀어쓴 설명 (UX-03)
  - 등기 권리별 인수/말소 분류 목록 + 각 분류의 근거 규칙 표시
  - 임차인 분석: 대항력 발생일 vs 말소기준일 비교, 확정일자·배당요구 반영, 소액임차인 해당 여부(담보 설정 시점별 개정 이력 테이블 적용)
  - **예상 총 부담액 자동 합산**: 입찰가 입력 시 [입찰가 + 인수 보증금 + 예상 취득세]를 자동 계산 (UX-02, L-07)
  - 예상배당표 (추정치 면책 문구 병행)
- 시스템은 "입찰 추천/비추천", "안전/위험 물건" 등 **판단·권유 문구를 출력해서는 안 된다** (변호사법 §109, D-011). 위험 신호는 사실 서술("매각물건명세서에 유치권 신고 기재가 있어요")로만 표시한다.

### F-04 위험 플래그 + 임장 체크리스트
- 시스템이 매각물건명세서·현황조사서에서 위험 키워드(유치권 신고, 지분매각, 대지권 미등기, 선순위 임차인, 토지별도등기 등)를 감지하면, 물건에 경고 배지를 표시해야 한다.
- 경고 표시 시, 시스템은 반드시 다음 행동(임장 체크리스트 항목, "전문가 확인이 필요한 항목이에요")을 함께 제시해야 한다 — 막다른 경고 금지 (UX-06).
- 임장 체크리스트는 물건별 자동 생성: 전입세대확인서 열람(주민센터), 점유자 확인, 관리비 체납 확인 등 온라인 불가 항목 (01 §5).

### F-05 용어 도우미
- 사용자 대면 화면의 모든 도메인 용어에 툴팁·풀어쓰기를 병기해야 한다 — 병기율 100% (UX-03). 문구는 해요체·능동형·긍정형 (T-09~13).

### F-06 관심 물건 + 알림
- 사용자가 물건을 관심 등록하면, 시스템은 기일 변경·유찰·취하 시 푸시 알림을 보내야 한다.
- 알림은 사용자가 등록한 물건에 한정한다 — 마케팅 푸시 별도 동의 (T-07 예상 밖 노출 금지).

### F-07 계정
- 소셜 로그인 3종(카카오·네이버·애플). 주민번호·본인인증 없음 (A-08, D-010). 비로그인으로도 탐색·권리분석 열람 가능, 관심 등록만 로그인 요구 (T-04 진입 방해 금지).

### F-08 개인정보·면책 (비화면 요구)
- 시스템은 경매 사건 종료(낙찰 확정·취하·기각)를 감지하면 해당 사건의 소유자명 등 개인정보를 지체 없이 마스킹/파기해야 한다 (PIPC 2019-05-057, A-08).
- 권리분석 화면 하단에 "참고 자료이며 법적 판단이 아님, 최종 확인 책임은 이용자" 면책 고지 상시 표시.

## 7. 성공 지표 (출시 후 3개월)

- 활성화: 신규 방문자의 권리분석 열람 전환율 ≥40% (핵심 가치 도달)
