# Seed Brief

- 원문 입력: "네이버부동산, KB부동산, 다방 같은 부동산 어플의 장점을 종합한 어플을 만들고 싶어. 여기에 경매 물건을 포함하는 플랫폼을 기획하고 싶거든. 우선은 3개의 플랫폼을 정밀 분석하고 어떤 기술 스택을 사용할지 보안은 어떻게 구성할지를 기획 설계할거고, 이들보다 직관적으로 사용할 수 있는 toss ui/ux 원칙을 최대한 적용해서 경매 매물까지 표시하고 해당 물건의 권리분석까지 진행해주는 플랫폼을 만들고 싶어. 어려운 부동산 용어 같은 도메인 지식이 없으니까 4지선다 같은 선택지나 쉬운 설명으로 인터뷰하며 진행하자."

- 솔루션 유형: B2C 부동산 통합 정보 플랫폼 (일반 매물 + 법원경매 물건 + 권리분석 자동화)
- 주 도메인: 부동산 정보 서비스 (매물 검색·시세·지도 탐색)
- 인접 도메인: 법원 부동산 경매 (권리분석·입찰 정보), 프롭테크 데이터 파이프라인, 모바일 컨슈머 UX

- 감지된 제약조건 (입력에서 읽어낸 것만):
  1. 벤치마크 대상 3개 고정: 네이버부동산, KB부동산, 다방 → 정밀 분석 필수
  2. 경매 물건 표시 + 해당 물건의 권리분석 기능 포함 필수
  3. 토스 UI/UX 원칙 적용 → 검증 가능 기준으로 변환 필요 (quality-decomposition 대상: "직관적으로 사용할 수 있는")
  4. 기술 스택 선정 + 보안 구성이 이번 기획 범위에 명시적으로 포함
  5. 사용자(기획 의뢰자)는 부동산 도메인 지식 없음 → 질문은 4지선다·쉬운 설명 형태로 제공

- 질적 표현 감지 (quality-decomposition 변환 대상):
  - "직관적으로 사용할 수 있는" → UX-NN 기준으로 변환 예정
  - "toss ui/ux 원칙" → references/ux-principles-kr.md의 T-NN/L-NN 개별 원칙 ID로 분해 적용
