# Assumption Pack

작성일 2026-07-07. 아래 가정은 사용자 답변으로 뒤집히기 전까지 현업 기본값으로 채택한다.

| A-01 | 플랫폼의 법적 지위는 "정보 제공·광고 매체"로 한정. 직접 중개·거래 알선·입찰 대행은 하지 않음 | 무등록 중개는 형사처벌(공인중개사법 §48). 직방·다방·네이버 모두 광고 매체 모델 (01-discovery §3-1) | 사업 모델 전체, 06 아키텍처 |
| A-02 | 자동 권리분석은 1단계(룰 엔진 완전 자동) + 2단계(위험 키워드 경고+임장 체크리스트)까지만. 특수물건(유치권 등) 판단은 "전문가 연결"로 처리하고 소프트웨어가 판단하지 않음 | 변호사법 §109 리스크 + 지지옥션도 특수권리는 사람이 분석 (01 §1-3, §3-1) | 핵심 기능 명세, 로드맵 전체 |

| A-11 | 사용자 대면 문구는 토스 UX 원칙(T-09~13)을 따르되, "토스처럼"이라는 표현 대신 04-proposal-cards의 UX-01~07 측정 기준으로 관리 | quality-decomposition 규칙 (형용사 금지) | 05 비기능 요구, 07 완료 기준 |

## 확인 질문 (최대 5개 중 4개 사용 — 답 안 하면 표기된 가정/추천안 적용)

1. **타깃 사용자 우선순위** — 경매 입문 일반인 / 투자자 / 일반 매물 탐색자 / 모두. 답 없으면: 경매 입문 일반인 우선 (기회 영역 분석 근거).
2. **MVP 범위** — 경매 특화 / 경매+일반매물 동시 / 데이터 분석 중심. 답 없으면: 경매 특화 MVP (A-04 연동).
3. **개발 체제와 주력 기술 경험** — 1인(웹/TS 경험) / 1인(Java·C# 등 백엔드 경험) / 2~3인 팀 / 외주·미정. 답 없으면: 1인 개발 가정.
4. **기술스택 방향** — TypeScript 올인원(1안) / Flutter+Spring(2안) / 추천안 위임. 답 없으면: 1안 채택 (C-01~03 추천 근거).

질문 5번 슬롯은 사용하지 않음 — 수익 모델은 A-03 가정으로 대체 (되돌리기 쉬운 결정 + 무료 시작이 법적으로도 안전).
