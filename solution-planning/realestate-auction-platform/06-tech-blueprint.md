## 2. 아키텍처 개요

```
[RN 앱] [Next.js 웹]
    │       │  (물건 상세 SSR = SEO)
    └───┬───┘
   [NestJS API]──[PostgreSQL+PostGIS]
        │              ▲
        │        (정규화된 사건/물건/권리 데이터)
   [권리분석 룰 엔진]     │
   (NestJS 모듈)      [수집 파이프라인 (Python 배치)]
        │              ├─ ① 법원경매정보 수집기 (신건/변경 감지, 일 1회+기일 임박 증분)
   [등기부 커넥터]        ├─ ② 법원 서류 PDF 파서 (매각물건명세서 → 위험 키워드)
   (CODEF/하이픈,        ├─ ③ 공공 API 수집기 (실거래가·건축물대장·토지대장)
    on-demand+캐시)      └─ ④ 개인정보 마스킹 배치 (사건 종료 감지 → 파기)
```

### 컴포넌트 설계 포인트

1. **수집 파이프라인 (D-007)**
   - courtauction.go.kr 수집: 요청 간격 제한(서버 부하 예절), 실패 시 CODEF 백업 경로 전환 가능한 인터페이스로 추상화. **약관 원문 확인이 Phase 0 선행 조건.**
   - 신선도 목표 NF-02 (24시간 내 반영 ≥99%) — 수집 성공률·지연 대시보드 필수.
   - 법원 서류 PDF는 원본 보존(Object Storage) + 파싱 결과를 별도 테이블로 — 룰 재실행 가능 구조.

2. **권리분석 룰 엔진 (D-011, F-03) — 이 시스템의 심장**
   - 입력: 파싱된 등기부(권리 목록+접수일) + 임차인 정보(현황조사서·매각물건명세서) + 소액임차인 기준 테이블(시행령 개정 이력 포함, law.go.kr 연혁 기준).
   - 출력: 말소기준권리, 권리별 인수/말소 분류 + **적용 규칙 ID**, 임차인 대항력 판정, 예상배당표. 모든 출력에 근거 규칙 추적 가능(감사 로그) — 오류 신고 대응(NF-01)과 면책 방어의 기초.
   - **룰은 버전 관리**: 판정 결과에 룰 버전 기록. 법령 개정 시 룰 테이블만 갱신.
   - 판단·권유 문구는 룰 엔진 출력에 존재하지 않음 — 문구 레이어는 별도 카피 사전에서 관리(변호사 검토 대상을 한 곳에 모음).

3. **등기부 커넥터 (D-008)**
   - on-demand: 사용자가 권리분석 탭 진입 시 발급 → 사건 단위 캐시(등기 변동 이벤트 전까지 재사용). 원가 = 열람 실비 700원/건 + API 요금 → 물건당 1회로 통제.
   - PoC는 CODEF 무료 데모(3개월, 일 100회)로 파싱 정확도 검증.

4. **개인정보 파이프라인 (A-08, NF-03)**
   - 스키마 설계 원칙: 소유자명 등 개인정보 필드는 전용 테이블 분리 + 사건 상태와 FK — 종료 감지 배치가 해당 테이블만 마스킹. 주민번호 필드는 스키마에 존재하지 않음.

5. **지도 어댑터 (D-006)**: 클라이언트 지도 호출을 자체 인터페이스로 감싸 공급자 교체 가능하게. 정책 변경 이력이 있는 외부 의존성 격리.

## 4. 보안 구성 (D-010 + 조사 §4-4)

| 항목 | 구성 |
|---|---|
| 인증 | 소셜 3종 OIDC/OAuth2, RFC 8725 준거 JWT — 액세스 15분 + 리프레시 회전(rotation) + 서버측 폐기 목록 |
| 개인정보 암호화 | 주민번호 미수집(필드 없음), 고유식별정보 저장 시 AES, 전송 TLS — 「개인정보의 안전성 확보조치 기준」 준거 |
| API 보호 | **비로그인 공개 API 금지**(익명 트래픽은 서명된 앱 토큰 요구 — 크롤링 형사 보호의 전제인 '접근제한 조치'), IP·계정·엔드포인트별 rate limiting, 응답 워터마킹(허위 좌표 심기)으로 민사 입증 자료 확보 |
| 앱 무결성 | Android Play Integrity(일 1만 건 무료), iOS App Attest |
| 감사 로그 | 개인정보 취급 접속기록 중앙화 (고시상 1년+ 보관) — ISMS-P 선행 항목 |
| 운영 | 운영/개발 계정 분리, DB 개인 계정 접근, 공용 root 금지 |

## 6. 초기 비용 모델 (월, MAU 1만 이하 추정 — 확정은 계산기 재검증)

- 인프라: 앱 서버 1~2대 + 관리형 PG + Object Storage ≈ 20~40만원 → 그린하우스 크레딧으로 상쇄 (최대 1억·2년)
- 등기부: on-demand 설계 시 "권리분석 실조회 물건 수 × 700원 + API 기본료(월 10만원~)" — MVP 최대 변동비. 월 3,000건 조회 가정 시 약 31만원
- 지도: 무료 한도 내 (모바일 월 1억)
- 합계 감: 크레딧 적용 시 **월 실지출 ~35만원 내외** (등기부 실비 중심)
